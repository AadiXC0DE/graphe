**The review screen was showing you the wrong half of the diff.** Side by side sized every row to the widest line in the file rather than to the pane it sits in, so with two columns the *after* side began past the right edge of the box. What you were reading was the before side, and for an added line that side is blank. A screen of new code read as a screen of nothing, with the code itself scrolled out of sight and no sign it was there. Split rows fit the pane now, and a line too long for its half wraps inside it. One column keeps the wide row and its sideways scroll, which is what that mode is for.

**And it was reading through a keyhole.** Two columns of width came off the code before it got any. The list of what is waiting held a single card next to a reading that already named the same entry at the top, so it is drawn once there are two entries to choose between. The diff drew its own list of the same files the screen had just listed above it with a decision on each, so beside a list it starts shut, remembered apart from the diff that has no list but its own. The fold key still opens it. On a wide window that is roughly twice the width for the change itself.

**The change now opens on its own.** The diff was only ever asked for by pressing a row in that list, so the reading sat on "Reading the change" until somebody pressed one. It asks for the entry it is showing.
